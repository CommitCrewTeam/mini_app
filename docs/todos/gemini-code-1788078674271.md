# Hướng Dẫn Kỹ Thuật Triển Khai PII Boundary & PCI Boundary Trong Microservices

---

## 1. PII Boundary (Dữ Liệu Cá Nhân & Tuân Thủ GDPR)

**Mục tiêu kỹ thuật chính:** Quản lý Vòng đời Chìa khóa (Key Lifecycle) & Mã hóa linh hoạt (Crypto Shredding).

### A. Quản lý Key bằng KMS (Key Management System)
* **Công cụ khuyến nghị:** AWS KMS, HashiCorp Vault, GCP KMS, Azure Key Vault.
* **Cơ chế Envelope Encryption (Mã hóa bao bọc):**
  1. Mỗi User có một **Data Encryption Key (DEK)** riêng biệt.
  2. DEK được dùng để mã hóa dữ liệu cá nhân của User đó (Họ tên, SĐT, Email, Địa chỉ).
  3. Bản thân DEK lại được mã hóa bằng một **Key Encryption Key (KEK / Master Key)** nằm an toàn bên trong KMS.
* **Quy trình Xóa dữ liệu GDPR (Right to be Forgotten):**
  * Khi User bấm xóa tài khoản: Hệ thống gửi API request lên KMS để **xóa vĩnh viễn DEK** của User đó.
  * **Kết quả:** Dữ liệu PII còn nằm trong DB, Kafka Log hay Backup File lập tức biến thành chuỗi rác vô nghĩa (unusable) mà không cần can thiệp xóa trực tiếp vào Database hay Event Streams.

### B. Triển khai Crypto Shredding (Code & Infra Architecture)
* **Tầng Application (Code Level):**
  * Sử dụng Custom Serializer / Interceptor (như Jackson Serializer trong Java, Custom TypeORM Transform trong Node.js, AOP Aspect).
  * Tự động bắt các field có annotation `@PII` để gọi KMS lấy DEK mã hóa trước khi `INSERT` vào DB hoặc `PUBLISH` lên Message Queue.
* **Tầng Infrastructure (Sidecar Pattern):**
  * Triển khai một Container **Sidecar** (ví dụ: Kafka Sidecar Proxy) đứng ngay trước Microservice.
  * Sidecar tự động chặn dữ liệu đầu ra/đầu vào, bắt tay với KMS để mã hóa/giải mã. 
  * **Lợi ích:** Code nghiệp vụ của Microservice hoàn toàn sạch sẽ, không phải tự quản lý logic mã hóa.

### C. An toàn dữ liệu ở tầng Log & Monitoring
* **Data Masking / Redaction:**
  * Cấu hình các Logger Framework (Logback, Winston, Log4j) sử dụng Masking Pattern cho các trường nhạy cảm trước khi đẩy ra Centralized Logs (ElasticSearch, Grafana Loki, Datadog).
  * **Ví dụ output:** 
    * SĐT: `090****123`
    * Email: `u***r@gmail.com`
    * Email/CCCD: `352******12`

## 2. PCI Boundary (Dữ Liệu Thanh Toán & Tuân Thủ PCI DSS)

**Mục tiêu kỹ thuật chính:** Cô lập Hạ tầng Mạng (Network Isolation) & Tuyệt đối KHÔNG lưu trữ dữ liệu thẻ trực tiếp.

### A. Kỹ thuật Tokenization (Cổng thanh toán bên thứ ba)
* **Tuyệt đối KHÔNG tự xử lý/lưu trữ dữ liệu thẻ thô (PAN, CVV, Expiry Date)** trừ khi hệ thống có chứng chỉ PCI DSS Level 1.
* **Quy trình Tokenization:**
  1. Sử dụng iFrame / SDK do đối tác Cổng thanh toán (Stripe, Adyen, VNPay, Zalopay) cung cấp trực tiếp trên Frontend.
  2. Khách hàng nhập thông tin thẻ $\rightarrow$ Data đi thẳng tới Server của Cổng thanh toán.
  3. Cổng thanh toán trả về một chuỗi **Token đại diện (Vô danh)**.
  4. PCI Boundary (`Payment Service`) chỉ lưu trữ chuỗi Token này để phục vụ các giao dịch tái chi trả (Recurring Payments / Auto-debit).

### B. Cô lập Hạ tầng Mạng (Network Segmentation)
* **VPC & Subnet Isolation:**
  * Đặt các PCI Microservices (`Payment Service`, `Billing Service`) vào một **VPC / Subnet / Kubernetes Namespace hoàn toàn riêng biệt**.
* **Strict Network Policies / Firewall Rules:**
  * Các Service ở vùng Non-sensitive **KHÔNG ĐƯỢC PHÉP** truy cập trực tiếp vào Database hoặc Network Subnet của PCI Boundary.
  * Mọi giao tiếp giữa vùng Non-sensitive và PCI Boundary phải đi qua **Internal API Gateway** được cấu hình whitelist IP khắt khe.
* **Mã hóa Truyền thông (In-Transit Encryption):**
  * Bắt buộc 100% kết nối nội bộ giữa các service trong PCI Boundary phải chạy **mTLS (Mutual TLS)** sử dụng Service Mesh (Istio, Linkerd).

### C. Audit Logging & Bastion Access Control
* **Immutable Audit Log (Chỉ ghi, không sửa/xóa):**
  * Mọi thao tác đọc/ghi vào vùng PCI phải được ghi Log và đẩy về dịch vụ lưu trữ theo chuẩn **WORM (Write-Once-Read-Many)** như AWS S3 Object Lock.
* **Bảo mật Truy cập Quản trị (Bastion & PAM):**
  * Cấm hoàn toàn SSH / Direct Exec vào Container/Server thuộc vùng PCI.
  * Mọi kết nối quản trị phải thông qua **Bastion Host / Privileged Access Management (PAM)**, bật xác thực 2 lớp (MFA) và được ghi hình (session recording) toàn bộ thao tác.

## 3. Bảng So Sánh Kiến Trúc Kỹ Thuật

| Tiêu chí | PII Boundary (Dữ liệu cá nhân) | PCI Boundary (Thanh toán) |
| :--- | :--- | :--- |
| **Trọng tâm Kỹ thuật** | Encryption & Key Management (KMS) | Network Isolation & Tokenization |
| **Xử lý Dữ liệu** | **Crypto Shredding** (Mã hóa theo User Key) | **Tokenization** (Đổi số thẻ lấy Token vô danh) |
| **Chiến lược Xóa** | Xóa Key trên KMS $\rightarrow$ Data thành rác | Xóa Token / Hủy liên kết Token |
| **Hạ tầng Mạng** | Co-exist trong hệ thống, cô lập về mặt mã hóa | Tách riêng **VPC / Subnet / Network Policy** khắt khe |
| **Quản lý Log** | Redact / Masking thông tin PII trên Central Log | Giữ Audit Log **Immutable (WORM)** phục vụ Audit |
| **Phạm vi Kiểm toán** | Nội bộ + Báo cáo GDPR Compliance | **External Audit độc lập** hàng năm bởi QSA |
